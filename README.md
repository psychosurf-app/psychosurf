# Психосерф

Telegram Mini App: дневник состояния после тренировок с советами спортивного психолога.

## Структура

- `web/` — экраны приложения (React + Vite)
- `server/` — сервер релиза 2 (Node.js + Express + PostgreSQL, Р-30): вход через Telegram, дневники и тренировки
- `docs/` — модель данных и технические заметки

## Правила кода (Р-33)

Тестовая сборка работает без сервера, сервер добавляется позже. Чтобы переход не стал переписыванием:

- `web/src/storage/` — единственное место, где сохраняются и читаются данные. Экраны не знают, где лежат записи. Сменить хранилище = заменить адаптер в `storage/index.js`. Сейчас: в Telegram — Telegram CloudStorage, в обычном браузере — localStorage, с `?demo` — только память. Если сборка сделана с адресом сервера (`VITE_API_URL=https://… npm run build`), в Telegram данные идут на сервер, а при первом запуске дневник переезжает туда из CloudStorage (`moveToServer.js`, в CloudStorage ничего не удаляется).
- `web/src/advice/` — единственное место, откуда приходит совет психолога. Сейчас всегда «закрыто», в релизе 2 — с сервера.
- `web/src/telegram.js` — единственное место, которое говорит с Telegram (Р-29).
- У каждой записи есть `version` (формат данных). Поменяли формат — подняли `SCHEMA_VERSION` и дописали `upgrade`.
- Платные советы в код приложения не кладём: любой может открыть код страницы.

Решения и задачи проекта — в таблице «Психосерф база» в Google Диске.

## Запуск экранов на своём компьютере

Нужен Node.js (версия LTS).

```
cd web
npm install
npm run dev
```

Открыть в браузере адрес, который покажет терминал (обычно http://localhost:5173).

## Сервер (релиз 2)

Код сервера публичный, секретов в нём нет: адрес базы, пароли и токен бота лежат только в файле `.env` на самом сервере (Р-34). Образец — `server/.env.example`.

Проверки запускаются без установки базы: тесты поднимают PostgreSQL в памяти (PGlite).

```
cd server
npm install
npm test
```

Те же тесты на настоящем PostgreSQL: `TEST_DATABASE_URL=postgres://… npm test` (каждый тест создаёт и удаляет свою схему).

Запуск с настоящей базой: заполнить `.env` по образцу и выполнить `npm start`. При старте сервер сам создаёт таблицы (`server/migrations/`). Проверка: `http://localhost:3000/api/health` отвечает `{"ok":true,"db":true}`.

### Адреса сервера

Все, кроме `/api/health`, требуют заголовок `Authorization: tma <initData>` из Telegram.

| Адрес | Что делает |
|---|---|
| `GET /api/health` | Жив ли сервер и база |
| `GET /api/me` | Профиль; первый заход создаёт пользователя |
| `GET /api/data` | Всё для экранов: профиль, дневники, тренировки |
| `PUT /api/profile` | Сохранить профиль |
| `PUT /api/diaries` | Сохранить список видов спорта (снятые скрываются, тренировки остаются) |
| `PUT /api/entries/:id` | Сохранить или изменить тренировку |
| `DELETE /api/entries/:id` | Удалить тренировку |
